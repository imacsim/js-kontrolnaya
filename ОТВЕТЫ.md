## Часть A. Почему так

### A1 — почему изменилось и у `a`
Потому что b копирует ссылку на объект из a, то есть и b, и a ссылаются на один и тот же объект в памяти, 
а значит, при изменении свойства через переменную b свойство также поменяется у переменной a.


### A2 — почему `3` раньше `2`
Потому что промис попадает в очередь микрозадач, а setTimeout(() => console.log("2"), 0) в очередь задач.
event loop сначала выполняет очередь микрозадач, а потом задач.


### A3 — почему счётчик остался нулём
Потому что стрелочная функция не имеет собственного this, а берет его из внешней области видимости.
Поэтому this ссылается на глобальный объект, а не на counter, и counter не изменяется.

## Часть B. Что было не так

Четыре находки. По каждой: в чём была проблема и что вы исправили.

### Ошибка 1

**Было не так:**
Не правильно удалялись задачи. В функцию removeTask(id) id приходил в виде строки.
tasks.find((t) => t.id === id): метод find ничего не находил из-за разных типов id и t.id и возвращал undefined.
tasks.splice(tasks.indexOf(task), 1): indexOf(undefined) возвращал -1 и splice() удалял последний элемент массива.

**Исправил:**
Использовал нестрогое равенство t.id == id
### Ошибка 2

**Было не так:**
Кнопка Только важные не работала.
tasks.filter((task) => task.priority >= 5): метод filter() не изменяет исходный массив, а возвращает новый отфильтрованный массив.
Новый массив нигде не сохранялся и массив task оставался прежним.
**Исправил:**
Перезаписать tasks: tasks = tasks.filter((task) => task.priority >= 5);
### Ошибка 3

**Было не так:**
Не работала сортировка по важности.
tasks.sort(): функция sort() преобразует объекты в строки. Все объекты становились равны "[object Object]" и ничего не сортировалось.

**Исправил:**
```
tasks.sort((a, b) => {
  if (a.priority > b.priority) return -1;
  if (a.priority < b.priority) return 1;
  return 0;
});
```
### Ошибка 4

**Было не так:**
Не правильно работал счетчик действий.
```
btn.addEventListener("click", function () {
    const countActions = createCounter();
    actionsEl.textContent = countActions();
});
```
const countActions = createCounter(): при каждом клике функция createCounter() запускалась заново.
Из-за этого переменная count внутри нее каждый раз пересоздавалась в 0 и потом становилась 1.

**Исправил:**
вынес const countActions = createCounter() за пределыобработчика событий
```
const countActions = createCounter();

document.querySelectorAll(".btn").forEach((btn) => {
    btn.addEventListener("click", function () {
        actionsEl.textContent = countActions();
    });
});
```
счетчик создается один раз.

## Часть C. Обоснуйте выбор

### C1 — какой вариант карточки и почему

**Выбираю:**
```
<a class="card" href="item.html?id=7">Название</a>
```
**Причины:**
Тег ```<a>``` предназначен для ссылки и сразу понятно в коде, что это ссылка.
Скринридеры объявляют как ссылку. Работает фокус. Можно открыть в новой вкладке. 
### C2 — какой вариант вывода списка и почему

**Выбираю:**
```
users.forEach((u) => {
  const li = document.createElement("li");
  li.textContent = u.name;
  list.append(li);
});
```
**Причины:**
Свойство textContent записывает данные как текст.
Если пользователь введет вредоносный код, то он просто отобразится как текст и не будет выполнен (в отличии от innerHTML).
innerHTML = ... пересоздает содержимое списка, а append добавляет новый элемент в конец списка и не трогает другие.
